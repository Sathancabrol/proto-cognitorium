C'est le cœur. **La vue « Mes possibilités » est la promesse du produit, et elle renvoie 0 pour le profil de référence.**

### R1 · ROME-01 — Remplacer le garde-fou binaire par une couche d'alignement lexical

**Ne pas faire :** baisser le seuil. Simulé et mesuré (`tools/audit/fix-simulation.mjs`) :

| Näthan | 0 | 141 — mais avec `K2419 Botaniste` et `K2420 Chercheur du monde forestier` à **97/100** |
| Pierre DENIAUD | 31 | **8** ⬇️ régression |
| Léa Martin | 0 | **0** — toujours cassé |

**À faire, en 3 couches :**

**1.a — Table d'alignement `skill → compétence référentiel` (le vrai correctif).**
Créer `src/data/skillAlignment.ts` : pour chaque compétence de profil, la ou les compétences ROME correspondantes, avec `confidence` et `source: 'manual' | 'llm_proposed' | 'validated'`.

```ts
export interface SkillAlignment {
  profileSkillName: string;          // « Méthodologie Expérimentale & Protocoles Scientifiques »
  romeSkillNames: string[];          // « Réaliser une veille scientifique », « Concevoir un protocole d'expérimentation »
  romeCodes: string[];               // ['K2403','K2402','H1213']
  method: 'exact' | 'curated' | 'llm_proposed';
  validatedBy?: string;
}
```

Génération assistée : un script (`scripts/build_skill_alignment.py`) propose via Gemini, **un humain valide** — exactement le motif « l'IA propose, l'humain valide » déjà appliqué aux nœuds, appliqué cette fois au *moteur*. ~80 compétences de profil à aligner sur les 6 profils actuels : **une demi-journée de validation humaine.**

**1.b — Scoring continu, plus de coupe à 0/1.**
Dans `computeFicheMatch`, remplacer `if (exactCount === 0) return { evaluated: false }` par un poids par type de correspondance :

```ts
const WEIGHT = { exact: 1.0, curated: 0.85, llm_proposed: 0.6, fuzzy: 0.35 };
const score = Σ(WEIGHT[m.matchType] × qualité(m)) — pénalité si < 2 correspondances
```

Et **afficher le type de correspondance dans l'UI** : « correspondance exacte » / « rapprochement validé » / « rapprochement proposé par l'IA ». C'est cohérent avec l'échelle épistémique déjà en place : un match flou est un **niveau 4 (hypothèse)**, un match validé un **niveau 2 (inférence)**.

**1.c — Supprimer la troncature à 40** (ROME-03). Remplacer `if (out.length >= 40) break;` par un tri par pertinence avant coupure : `sort((a,b) => b.tokenOverlap - a.tokenOverlap).slice(0, 60)`. Sans tri, le résultat dépend de l'ordre d'itération d'une `Map`.

**Critère d'acceptation (mesurable) :**

| Profil | Avant | Cible |
|---|---|---|
| Näthan | 0 | ≥ 20 résultats, **dont ≥ 5 au label `forte` ou `tres_forte`** |
| Léa Martin | 0 | ≥ 8 résultats |
| Thomas Valadier | 0 | ≥ 12 résultats |
| Pierre DENIAUD | 31 | **≥ 31** (pas de régression) |
| Amélie / Gianni | 8 / 5 | ≥ 8 / ≥ 15 |

Et **zéro** métier manifestement absurde dans les 10 premiers de chaque profil (revue manuelle des 60 premiers — c'est le vrai test, pas le nombre).

**Réutiliser** : `computeFicheMatch` calcule déjà `missingSkills`, `formations`, `experiences`, `unverifiedCount`, `coverageRatio`. Tout est là, seul le seuil d'entrée bloque.

## S3 — Données : combler le niveau « tâche » (4-5 jours)

C'est le chantier le plus important pour la **crédibilité scientifique** du produit, et le plus long.

### T1 · Le modèle à 5 niveaux est amputé de son pivot

| Profil | Tâches | Compétences | Ratio |
|---|---|---|---|
| Näthan | 8 | 19 | 0,42 |
| Gianni | **2** | 16 | **0,13** |
| Amélie | **2** | 9 | **0,22** |

La tâche est ce qui transforme une compétence **déclarée** en compétence **prouvée**. `computeFicheMatch` remonte explicitement `demonstrates_skill → composed_of → expérience` pour remplir `experiences` : sans tâche, ce panneau est vide et la « traçabilité des preuves » — le nom du produit — n'est pas démontrable.

**Cible :** ≥ 3 tâches par expérience, chaque compétence reliée à ≥ 1 tâche par une arête `demonstrates_skill`. Soit, pour les 4 profils réels : **~120 tâches à écrire**. Les sources sont déjà dans `raw/` (CV, rapports de stage, dossiers chantier) — c'est du dépouillement, pas de l'invention.

**Méthode建议 :** un script d'aide à l'extraction (`scripts/extract_tasks.py`) qui propose des tâches par lecture des CV, puis **validation humaine systématique**. Ne pas laisser l'IA écrire les tâches seule : ce sont des faits de niveau 1.

`EVALUATIONS_BY_PROFILE` n'a qu'une clé (`evaluationsCatalog.ts:215-217`). Les 5 autres profils ouvrent « Mes évaluations » sur un catalogue vide.

**Cible :** ≥ 10 évaluations par profil, avec la répartition déjà en place (`diplome`, `certification`, `verification`, `evaluation`, `test_psy`, `physio`, `bci`). Les 7 familles et leurs garde-fous (« Jamais un diagnostic automatique ») sont déjà codés — il manque les données.
