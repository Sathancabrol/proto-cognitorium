## 2. Ce qui fonctionne — dit clairement, parce que c'est réel

Il faut le dire avant les problèmes, sinon le diagnostic est faussé :

- **Aucun plantage.** 143 rendus réels (15 vues × 6 profils + 23 composants isolés + 30 combinaisons profil/vue) : **0 exception React, 0 `console.error`**. TypeScript strict : 0 erreur. Le build passe.
- **Le centre de validation humaine fonctionne.** Testé par clics : badge « 16 à valider » → clic « Valider » → **compteur passe à 15** → clic « Tout valider » → **le badge disparaît**. Le flux « l'IA propose, l'humain valide » est réellement câblé.
- **Le référentiel ROME est propre et complet** : 1 911 fiches, **1 911 codes uniques**, 17 920 clés `SKILL_TO_ROME`, 17 722 compétences distinctes, 46 198 associations compétence→code, 14 grands domaines. **0 clé orpheline** dans `ROME_CODE_SKILLS` ni dans `ROME_FORMACODE`. **1 911/1 911 fiches ont un mapping FORMACODE** (moyenne 2,4 formations/fiche). Seules 2 fiches (C1129, C1216) n'ont aucune compétence dans l'arborescence.
- **L'échelle épistémique tient sa promesse.** `epistemics.ts` ne peut **structurellement pas** renvoyer le niveau 5 : `EpistemicLevel['level']` est typé `1 | 2 | 3 | 4`. Une « conclusion psychologique » ne peut donc pas être produite par le code. C'est un vrai garde-fou, pas un commentaire.
- **Les contenus sont denses et sourcés** : 92 ressources OER (+268 au total), 30 œuvres dans `PSYREF_LIBRARY`, 22 sources dans `PSYREF_SOURCES` avec hiérarchie de preuves en 6 niveaux, 5 journaux clés, 176 fiches d'outils (91 éval + 85 data), 21 citations avec compteur de citations, 15 protocoles expérimentaux **tous dotés d'une démo interactive réelle** (`LAB_DEMOS` couvre les 15 identifiants), 230 URLs et 22 DOI.
- **Le moteur de déclin est cohérent** : 19 compétences pour Näthan, demi-vies de 5 à 12 ans, plancher résiduel 35 %, 16 compétences dormantes projetées en 2035. Le calcul est explicable ligne à ligne.

**Diagnostic d'ensemble :** ce prototype n'est pas cassé. Il est **bien construit et mal raccordé**. Les bugs sont des bugs de *jonction* entre un bon moteur et de mauvaises données d'entrée — pas des bugs d'architecture.

## 3. Les bugs — avec la preuve, pas l'intuition

### 🔴 ROME-01 — La vue phare affiche « 0 correspondance » pour le profil de référence

**Symptôme vu par l'utilisateur.** Capture du texte réellement rendu par `HorizonsBridge` (profil Näthan, rendu serveur réel) :

> « Moteur ROME — Matching explicable […] **Top 0 correspondances calculées depuis votre profil** […] **Aucune correspondance pour cette recherche.** […] Mes horizons détectés (5) »

L'écran annonce donc **zéro** métier, puis affiche **cinq** horizons « Très forte » juste en dessous. C'est très probablement la « feature qui déconne » que vous avez vue.

**Mesure.** `computeAllRomeMatches(profil, 60)` exécuté sur les 6 profils :

| Profil | Correspondances | Correspondances exactes de compétences |
|---|---|---|
| **Näthan Cabrol (référence)** | **0** | **0 / 19** |
| Amélie Cruagnes | 8 | 4 / 9 |
| Gianni Ducoeur | 5 | 3 / 16 |
| Pierre DENIAUD | 31 | 11 / 14 |
| **Léa Martin** | **0** | 0 / 2 |
| **Thomas Valadier** | **0** | 0 / 2 |

**Cause racine, localisée.** `src/utils/romeMatching.ts` :

- `getRomeCodesForSkill()` renvoie `matchType: 'exact'` **uniquement** si `SKILL_TO_ROME[nomNormalisé]` existe — c'est-à-dire si le nom de la compétence du profil est **mot pour mot** celui du référentiel France Travail.
- `computeFicheMatch()` lignes ~191-208 : `if (exactCount === 0) return { …, evaluated: false }`, avec le commentaire « *Exiger au moins une correspondance EXACTE : sinon la fiche est du bruit* ».

Les compétences de Näthan sont rédigées en langue « CV de chercheur » (« Méthodologie Expérimentale & Protocoles Scientifiques »), pas en langue « arborescence ROME » (« Réaliser une veille scientifique »). Résultat : **18 compétences sur 19 ne matchent qu'en flou**, donc `exactCount = 0` partout, donc `evaluated = false` sur les **1 911 fiches**.

**Ampleur réelle du gâchis.** Recalcul manuel : les compétences de Näthan touchent **369 fiches ROME** via le matching flou. **369 métiers sont écartés par le garde-fou.** Parmi eux : `K2403 Biostatisticien`, `H1213 Responsable du développement clinique`, `H1224 Technicien de laboratoire R&D`, `K2135 Ethnologue`. Ce sont précisément les passerelles que le produit promet de révéler.

**Piège à éviter dans le correctif.** J'ai simulé la relaxation naïve (accepter le flou dès 2 convergences) :

| Profil | Actuel | Flou ≥ 2 |
|---|---|---|
| Näthan | 0 | **141** |
| Gianni | 5 | 87 |
| Thomas | 0 | 9 |
| **Pierre DENIAUD** | **31** | **8** ⬇️ |
| Léa Martin | 0 | **0** (toujours) |

Et le top devient absurde : pour Näthan, `K2419 Botaniste` et `K2420 Chercheur du monde forestier` sortent à **97/100**. **Baisser le seuil casse Pierre et noie Näthan sous le bruit.** La vraie correction n'est pas un seuil : c'est une **couche d'alignement lexical** compétence-profil ↔ compétence-référentiel (voir roadmap R1).

### 🔴 IA-02 — L'onboarding reproduit le bug que `CONSOLIDATION.md` déclare corrigé

`CONSOLIDATION.md`, point 11 : *« Fini « toutes les compétences → toutes les capacités » et « première capacité → tous les métiers ». »*

C'est vrai dans `ExperienceDistillerModal.tsx` (correspondance par nom normalisé, `mapSkillRefs`). **Ce n'est pas vrai dans `OnboardingModal.tsx`**, qui duplique tout le pipeline d'extraction. Lignes ~96-134, vérifiées :

tasks.forEach((task) => {

(capacities || []).forEach((c) => {

(potentialJobs || []).forEach((j) => {

## 4. Lecture UX / psychologie — le vrai risque produit

Au-delà des bugs, trois problèmes de conception :

**1. Le produit promet la rigueur épistémique et la contredit dans son parcours principal.**
Le garde-fou est réel et bien codé (`epistemics.ts` ne peut pas produire de niveau 5). Mais sur l'écran le plus vu : « Top 0 correspondances » à côté de 5 horizons « Très forte » non calculés (DATA-01), un RIASEC présenté avec « Réf #QDE-2025-38377 » — un numéro qui ressemble à une référence officielle pour un **auto-rapport**, et une signature cognitive à `transferabilityIndex: 85` pour un profil vide (IA-02). **Un utilisateur compétent repère l'incohérence en 30 secondes** — et c'est précisément votre cible (sciences cognitives, ergonomie, orientation).

**2. Le modèle à 5 niveaux est amputé de son niveau pivot.**
Expérience → **Tâche** → Compétence → Cognition → Matching. La tâche est ce qui rend une compétence *prouvable* plutôt que *déclarée*. Avec 2 tâches pour 16 compétences (Gianni), la chaîne de preuve est une promesse non tenue — et `computeFicheMatch` est explicitement écrit pour remonter `demonstrates_skill → composed_of`. Le moteur est prêt, les données ne le sont pas.

**3. Charge cognitive : 15 vues, 6 sections, aucun parcours guidé.**
`SECTION_OF_TAB` déclare 15 onglets. Le premier écran propose simultanément : 6 profils, 6 sections, des modes de représentation secondaires, un mode essentiel/expert, un compteur « 16 à valider », un bouton reset, un FAB. Pour un produit dont le sujet est la **métacognition et la régulation de l'apprentissage**, l'interface ne pratique pas ce qu'elle prêche. `SECTION_VIEWS.competences` ne contient qu'**une** entrée, donc le `Header` n'affiche jamais sa barre de modes pour cette section (`length > 1` requis) — la vue « Matrice de maîtrise » n'a pas de bouton, elle existe seulement comme défaut.
