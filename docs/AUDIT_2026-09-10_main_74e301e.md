### 🔴 `SEC-04` — « authentication flow » sans authentification (P0)

Le message de commit annonce *implement authentication flow*. Il n'y a
**aucune authentification**, ni côté serveur ni côté client.

Côté serveur — `server.ts` ne contient **aucune** de ces chaînes :

```

Authorization:0  login:0  signup:0  register:0

```

```

```

Côté client :

```
grep -rniE "password|mot de passe" src/  -> 0 occurrence
grep -rn 'type="password"' src/          -> 0 occurrence
grep -rn "setAuthStep('LOGIN')" src/     -> 0 occurrence
```

`AuthFlowStep` déclare pourtant `'LOGIN'` parmi ses 6 états
(`src/types/authTypes.ts`) : **c'est un état mort**, jamais atteint.

Ce que l'« authentification » est réellement : trois clés `localStorage`
(`cognitorium_auth_accounts_v2`, `cognitorium_custom_profiles_v2`,
`cognitorium_active_user_v2`) plus un drapeau `sessionStorage`
(`cognitorium_session_active_v2`, `App.tsx:51`), et un compte codé en dur dans
`App.tsx:53` :

```ts
const DEFAULT_ACCOUNTS: UserAccount[] = [{
  id: 'usr_nathan_cabrol',
  email: 'nathan.cabrol@cognitorium.fr',
  …

```

> **« Portail d'Accès & Authentification »** · « Environnement Épistémique •
> **Données Privées & Locales** » · « **Connectez** votre capital cognitif »

Un écran qui promet confidentialité et connexion, devant un sélecteur de profil
sans contrôle d'accès. C'est trompeur pour l'utilisateur et dangereux pour la
suite : `UserAccount` comporte `lastLoginAt`, `hasCompletedOnboarding`,
`profileId` — le modèle de données d'une vraie auth existe déjà, il ne reste plus
qu'à brancher un backend dessus, et rien dans le code n'indique que ce qui
précède n'est pas une auth.

de fausse authentification, dont une morte.
